# Alpha SDK — Sync Spec, Docs & MCP

## Overview

`api/openapi.yaml` is the single source of truth. Three things derive from it, all
in this same repo, and a change is not done until each affected one is updated **in
the same PR**:

1. **Client SDKs** — TypeScript (`@alpha-sdk/client`) and Python (`alpha-sdk-client`),
   generated by Fern. Never hand-edit them; the `sdk-preview` CI job regenerates
   them from the spec.
2. **MCP camera-control tools** (`mcp/`) — a 1:1 endpoint is a *generated* flat tool;
   an orchestrated one (sequence, bounded wait, session state, SSE) is a
   *hand-written* composite.
3. **Documentation site** (`site/src/content/docs/`) — guides + the API reference
   (the reference renders from the spec directly).

## Workflow

When you change `api/openapi.yaml`:

1. **Regenerate the MCP tools.** Run `crsdk gen:mcp`. The coverage gate in
   `mcp/scripts/gen-tools.mjs` fails until every spec operation is classified, so
   add a new flat-eligible endpoint to the tool manifest, or to the `HANDWRITTEN` /
   `NOT_EXPOSED` allowlist with a reason. Commit the regenerated
   `mcp/src/tools/generated.ts` (+ `schema.d.ts`, `property-names.ts`).
2. **Add a hand-written composite** in `mcp/src/tools/*.ts` if the tool needs
   orchestration (several client calls, ordering quirks, settle-polling, session
   state, or the SSE stream). List its consumed operationIds in `HANDWRITTEN`.
3. **Update the docs.** Edit the relevant page under `site/src/content/docs/`
   (e.g. `web-api/*` for endpoints, `web-api/compatibility` for model-specific
   behaviour). The API reference itself needs no edit — it renders from the spec.
   Build with `npm --prefix site run build`.
4. **Do not touch the clients.** Just review the `sdk-preview` artifact on the PR;
   a rename or removal there means you introduced a breaking change.
5. **Keep it backwards-compatible** — add, don't remove/rename/retype; deprecate
   instead of deleting. See `CONTRIBUTING.md` › Backwards Compatibility.

## Guardrails

- A PR that changes `api/openapi.yaml` with no `site/` docs change and no MCP
  regeneration will fail CI (`spec-docs-sync` + the `mcp` drift job). Update all
  three surfaces before pushing.
- Regenerated files are committed, not gitignored — run `crsdk gen:mcp` locally and
  commit the diff, don't rely on CI to produce it.

## Verify before opening the PR

```bash
crsdk gen:mcp && crsdk build:mcp && npm --prefix mcp test
npm --prefix site run build
```
