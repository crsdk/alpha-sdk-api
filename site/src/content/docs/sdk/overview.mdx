There are **TypeScript and Python client SDKs**, installable via npm / pip. They're
auto-generated from `api/openapi.yaml` on every PR, so they always track the real
server. For any other language, generate your own client from the same spec:

```
https://crsdk.github.io/alpha-sdk-api/api-reference/openapi.yaml
```

## Published clients

The TypeScript and Python clients are generated from the spec with
[Fern](https://buildwithfern.com) and published — install them like any package:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```bash
npm install @alpha-sdk/client
```

```ts
import { AlphaSDKClient } from "@alpha-sdk/client";

const client = new AlphaSDKClient({ environment: "http://localhost:8080" });
const { cameras } = await client.cameras.list();
```

</TabItem>
<TabItem label="Python">

```bash
pip install alpha-sdk-client
```

```python
from alpha_sdk_client import AlphaSDKClient

client = AlphaSDKClient(base_url="http://localhost:8080")
cameras = client.cameras.list()
```

</TabItem>
</Tabs>

Both are versioned together and released from the spec — see
[how the clients are generated and published](https://github.com/crsdk/alpha-sdk-api/blob/main/docs/SDK_GENERATION.md).

## Generate for another language

TypeScript and Python are published above — for anything else, point an OpenAPI
generator at the spec. A few examples:

<Tabs syncKey="generator">
<TabItem label="Swift">

```bash
# Add the Swift OpenAPI Generator plugin to Package.swift, drop the spec at
# Sources/<Target>/openapi.yaml, then build.
swift package plugin --allow-writing-to-package-directory generate-code-from-openapi
```

</TabItem>
<TabItem label="C#">

```bash
dotnet tool install --global Microsoft.OpenApi.Kiota
kiota generate -l CSharp \
  -d https://crsdk.github.io/alpha-sdk-api/api-reference/openapi.yaml \
  -o ./CameraClient
```

</TabItem>
<TabItem label="Any language">

```bash
# openapi-generator supports ~50 languages; swap the -g target.
npx @openapitools/openapi-generator-cli generate \
  -i https://crsdk.github.io/alpha-sdk-api/api-reference/openapi.yaml \
  -g go \
  -o ./camera-client
```

</TabItem>
</Tabs>

Pin the specification file into your repository rather than fetching it at build
time if you want reproducible builds — it is a single YAML file.

## What the API looks like

The operations are grouped by tag, and a generated client will mirror that
grouping:

```
server        health, status, logs
cameras       list, connect, disconnect, getConnectionStatus
properties    get, set, getAll, getPriorityKey, setPriorityKey
actions       shutter, halfPress, afShutter, zoom, focusNearFar, movieRec
liveView      enable, disable, getStatus, start, stop, getFrame
sdCard        list, download, downloadThumbnail, downloadScreennail
settings      download, upload, list, importLut
```

Two things sit outside what a generator will give you, because they are not
plain request/response operations:

- **Server-Sent Events** — the two event streams are long-lived and most
  generators will not produce anything usable for them. Consume them with native
  `EventSource` (browser) or `httpx.stream` (Python). See the
  [SSE recipe](/alpha-sdk-api/sdk/recipes/sse-events/).
- **Discovery, reconnect and lifecycle handling** — application concerns rather
  than API surface. The recipes below cover the usual patterns.

:::caution
Set the priority key to `pc-remote` before the camera will accept remote
property changes or shooting commands. This trips up most first integrations —
see [Connection](/alpha-sdk-api/web-api/connection/).
:::
