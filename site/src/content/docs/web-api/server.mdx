The REST API is a single native binary, `CameraWebApp`, that runs on the machine
the camera is physically attached to. Everything else — the
[API reference](/alpha-sdk-api/api-reference/), any
[client you generate](/alpha-sdk-api/sdk/overview/) — talks to it over HTTP.

:::note
There is no package to install — the server is built from source. The quickest
path is the [`crsdk` CLI](/alpha-sdk-api/cli/): `crsdk install --zip <sony-sdk.zip>`,
then `crsdk build`. The Sony Camera Remote SDK it links against must be downloaded
by accepting Sony's licence on the
[official Sony download page](https://support.d-imaging.sony.co.jp/app/sdk/en/index.html),
so it cannot be fetched automatically.
:::

## Run it

```bash
crsdk start        # or run the built binary directly: CameraWebApp
```

The server listens on `http://localhost:8080` and prints its startup banner. It
handles `SIGINT` and `SIGTERM`, so <kbd>Ctrl</kbd>+<kbd>C</kbd> shuts it down
cleanly — cameras are disconnected and open SSE streams closed before it exits.

### Options

| Flag | Default | Description |
| --- | --- | --- |
| `--port`, `-p` | `8080` | Port to listen on. Must be 1–65535. |

```bash
CameraWebApp --port 9000
```

That is the complete set of flags. Anything else on the command line is ignored.

## Running it from your own application

The server is an ordinary process, so any language that can spawn a subprocess
can supervise it — start it, wait for `/api/server/status` to answer, and stop
it on exit. See the
[server subprocess recipe](/alpha-sdk-api/sdk/recipes/server-subprocess/) for a
worked example including port selection and readiness polling.

## Health and control endpoints

See the [API reference](/alpha-sdk-api/api-reference/) for full request and
response schemas.

### Server status

`GET /api/server/status` returns server version, uptime, platform, and camera
counts. Poll this to confirm the server is ready before issuing other calls.

<Tabs>
<TabItem label="curl">

```bash
curl http://localhost:8080/api/server/status
```

</TabItem>
<TabItem label="Response">

```json
{
  "success": true,
  "server": {
    "version": "3.0.0",
    "sdkVersion": "V2.01.00",
    "uptime": 42,
    "platform": "darwin-arm64"
  },
  "cameras": {
    "connected": 1,
    "discovered": 2
  }
}
```

</TabItem>
</Tabs>

### Server logs

`GET /api/server/logs` returns buffered server log output.

Query params: `lines` (default 100, clamped to the retained buffer) and `level`
(default `info`, one of `debug` / `info` / `warn` / `error` — entries at or above
the given level are returned). A non-numeric `lines` or an unrecognised `level`
falls back to the default rather than erroring.

The response reports both `total` (everything retained) and `returned` (what
survived the filter), so a filtered response is not mistaken for data loss.

<Tabs>
<TabItem label="curl">

```bash
curl http://localhost:8080/api/server/logs
```

</TabItem>
<TabItem label="Response">

```json
{
  "success": true,
  "logs": [
    {
      "timestamp": "2026-03-02T12:18:45",
      "level": "info",
      "message": "GET /api/server/status"
    }
  ],
  "returned": 1,
  "total": 47
}
```

</TabItem>
</Tabs>

### Shutdown

`POST /api/server/shutdown` initiates graceful shutdown: disconnects all
cameras, closes open SSE streams, then exits. Prefer this over sending a signal
when shutting the server down from another process — it lets the camera
disconnect cleanly.

```bash
curl -X POST http://localhost:8080/api/server/shutdown
```
